# Spelling the app checks itself (2026-10-19)

**Outcome (2026-10-19): built.** The pieces below, as planned; one bug the flow test caught (the menu's
`ctxRun` closed the menu, clearing the clicked word, before the correction ran — the word is now passed
in). Verified: 750 unit tests (9 new — the words, the checker on the real en/es dictionaries, the client
with its real worker, the mark at the cursor), 174 server tests (the dictionary's round trip), the 22
flow tests at 1280 and 390 px (a new one: mark, correct, Add to dictionary, take it back in Settings),
and the built desktop app's own worker and dictionary chunks answering from app:// (RESEARCH, "The
writer's editor").

**Why.** The desktop app's spellchecker is Chromium's, through Electron, and on Windows it flags
nothing since Electron 41: electron/electron#54729 (bisected there to 40.10.6 working, 41.10.7
broken; closed by a bot for its template, never triaged). Measured here the same day: Electron
40.10.6 underlines "walkd" and suggests "walked"; 41.10.7, 44.7.0 (ours), 44.9.0 (latest) and
45.0.0-beta.5 draw nothing; Chrome 149 on the same box draws the squiggles. So JustWrite's desktop
app had no spelling on Windows while What's new promised it. Pinning Electron 40 is out (out of
support; the server runs on Electron's Node). Decided under the user's "keep going your rec"
(2026-10-19).

## The pieces, each with its standard

| Piece | Standard | Notes |
|---|---|---|
