# Spelling the app checks itself (2026-10-19)

**REMOVED the same day (2026-10-19) — its premise was false.** Electron's spellchecker works on
Windows with real typing (the user saw it underline in Just House Paint, Electron 44.7). What "flagged
nothing" was my probes' input: a box focused by script and fed only `char` events, which Electron 41+
never checks (RESEARCH, "Electron's spellchecker works on Windows — with real input"). The note before
this plan had said real input wasn't ruled out and asked for one look in the desktop app; the plan
went ahead without it. The user: "it should be removed it would have never been built in first
place", then "go back to electron". Reverted: the checker, the book's dictionary (table, snapshot,
store actions, Settings card, its Spanish), the inline editors' spelling menu, the flow test and
NOTICE entries; the spelling help is back to the browser's checker. Kept below as the record.

**Outcome (2026-10-19): built.** The pieces below, as planned; one bug the flow test caught (the menu's
`ctxRun` closed the menu, clearing the clicked word, before the correction ran — the word is now passed
in). Verified: 750 unit tests (9 new — the words, the checker on the real en/es dictionaries, the client
with its real worker, the mark at the cursor), 174 server tests (the dictionary's round trip), the 22
flow tests at 1280 and 390 px (a new one: mark, correct, Add to dictionary, take it back in Settings),
and the built desktop app's own worker and dictionary chunks answering from app:// (RESEARCH, "The
writer's editor").

**Why.** The desktop app's spellchecker is Chromium's, through Electron, and on Windows it flags
nothing since Electron 41: electron/electron#54729 (bisected there to 40.10.6 working, 41.10.7
broken; closed by a bot for its template, never triaged). Measured here the same day: Electron
40.10.6 underlines "walkd" and suggests "walked"; 41.10.7, 44.7.0 (ours), 44.9.0 (latest) and
45.0.0-beta.5 draw nothing; Chrome 149 on the same box draws the squiggles. So JustWrite's desktop
app had no spelling on Windows while What's new promised it. Pinning Electron 40 is out (out of
support; the server runs on Electron's Node). Decided under the user's "keep going your rec"
(2026-10-19).

## The plain text boxes (proposed 2026-10-19 — the layer waits for the user's word)

**Why.** JustWrite's 28 `UiTextarea` boxes (a character's fields, a scene's notes and Summary, the
premise, an event's notes, a strand's blurb, the describe box, the chat box, the AI review's
proposals) still use Chromium's spellchecker, so the Windows desktop app checks none of them. The
upstream report isn't filed (the user, 2026-10-19: "dont post bug report … find another
solutions"), and no app-side switch brings Chromium's back — Electron's own
`webFrame.setSpellCheckProvider` is never asked on 41+ (RESEARCH, "No app-side switch brings it
back on 41+").

| Piece | Standard | Notes |
